{{ include "ldap-manager.name" . }} {{ .Chart.Version }} (LDAP Manager {{ .Chart.AppVersion }})
{{ include "ldap-manager.fullname" . }} is deployed in namespace {{ .Release.Namespace }}.

Reach the UI:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "ldap-manager.fullname" . }} 8000:{{ .Values.service.port }}
  # then open http://localhost:8000{{ .Values.contextPath }}

{{ if .Values.ingress.enabled -}}
Ingress is enabled; check the address the controller assigned:

  kubectl -n {{ .Release.Namespace }} get ingress {{ include "ldap-manager.fullname" . }}
{{- else -}}
The Service is {{ .Values.service.type }}, so it is only reachable inside the
cluster. Use the port-forward above, or set ingress.enabled=true.
{{- end }}

config.yml:

{{ if .Values.config.existingConfigMap -}}
  You supplied ConfigMap {{ .Values.config.existingConfigMap }}; the chart rendered none.
  Mounted read-only at {{ .Values.config.mountPath }} and read via
  LDAP_MANAGER_CONFIG={{ include "ldap-manager.configFile" . }}.
{{- else -}}
  Rendered into ConfigMap {{ include "ldap-manager.configMapName" . }} and mounted read-only at
  {{ .Values.config.mountPath }}; the pod reads LDAP_MANAGER_CONFIG={{ include "ldap-manager.configFile" . }}.
  Edit it in place - the app re-reads the file on every request, no restart:

    kubectl -n {{ .Release.Namespace }} edit configmap {{ include "ldap-manager.configMapName" . }}

{{- if not .Values.config.clusters }}
  NOTE: config.clusters is empty, so the UI will show no clusters to manage.
{{- end }}
{{- end }}

Credentials:

{{ if .Values.secrets.existingSecret -}}
  Bind passwords come from the existing Secret {{ .Values.secrets.existingSecret }} (envFrom).
  A cluster with credential.source: env reads
    LDAP_MANAGER_CLUSTER_<CLUSTER_NAME>_PASSWORD
  where the cluster name is upper-cased and every run of non-alphanumeric
  characters becomes a single underscore.
{{- else if .Values.secrets.create -}}
  The chart created Secret {{ include "ldap-manager.secretName" . }} from secrets.env.
  Values live in the release, so `helm get values` shows them; prefer
  secrets.existingSecret for anything real.
{{- else -}}
  WARNING: no Secret is wired up. Clusters using credential.source: env will find
  no password. Either create one -

    kubectl -n {{ .Release.Namespace }} create secret generic {{ include "ldap-manager.fullname" . }}-secrets \
      --from-literal=LDAP_MANAGER_CLUSTER_EXAMPLE_CLUSTER_PASSWORD='...' \
      --from-literal=LDAP_MANAGER_CONFIG_EXAMPLE_CLUSTER_PASSWORD='...' \
      --from-literal=LDAP_MANAGER_SECRET_KEY="$(openssl rand -hex 32)"

  and set secrets.existingSecret. There is no way to store a password at runtime,
  so credential.source must be env or file for every cluster.
{{- end }}

Persistent state:

  {{ include "ldap-manager.dataClaimName" . }}     -> /app/.data     (audit log)
  {{ include "ldap-manager.secretsClaimName" . }}  -> /app/.secrets  (local-user key, session key)
{{- if not .Values.persistence.cache.enabled }}
  /app/.cache is an emptyDir: the encrypted password cache is rebuilt after a restart.
{{- end }}

Health:

  curl -s localhost:8000/health           # 200 healthy; 503 when config is invalid or a cluster is down
  curl -s localhost:8000/api/auth/status  # 200 whenever the app is serving (what the probes use)

Logs:

  kubectl -n {{ .Release.Namespace }} logs -f deploy/{{ include "ldap-manager.fullname" . }}
